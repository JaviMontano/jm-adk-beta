Cómo funciona

1

Catálogo = fuente única

Editas catalog/skills.json + runtime/core.md + profiles/. scripts/build-indexes.py genera las superficies de cada runtime. Editar el generado a mano se pierde al regenerar.

2

Contexto por capas (ICM)

5 capas bajo demanda (L0 identidad → L1 workspace → L2 stage → L3 refs → L4 output). Un sensor mide el stack de tokens antes de cargar — ≤8k por etapa, no 30-50k de golpe.

3

Gates = artefactos

scripts/check-prerequisites.sh --phase pN --json verifica que los artefactos existan. Constitution v7 MUST/MUST NOT extraídos y respetados en cada fase de ejecución. Un sensor de consistencia atrapa drift entre docs y fuente.

Preguntas frecuentes

¿Puedo editar CLAUDE.md / AGENTS.md / GEMINI.md a mano?

No. Son superficies generadas. Edita la fuente canónica (catálogo, runtime core, delta o profiles) y regenera con build-indexes.py. Los cambios a mano se pierden al regenerar.

¿Qué runtime uso primero?

El que ya tengas. Claude Code lee CLAUDE.md, Codex lee AGENTS.md, Antigravity lee GEMINI.md. Los tres salen del mismo catálogo.

¿Cómo elijo perfil?

vibe-coder para software runnable. knowledge-worker para investigación o documentos con fuentes. El perfil activa reglas de marca, calidad y comercial cuando el entregable pertenece al ecosistema MetodologIA.

¿Qué hace si le pido algo ambiguo?

Emite coverage_gap y pregunta antes de editar. No adivina. No edita sobre supuesto.

¿Puede mostrar precios?

No en output. Esfuerzo en FTE-months + disclaimers (regla governance). El pricing es profile-scoped.

What it is

Pristino Beta is an agentic harness. The catalog catalog/skills.json is the single source of truth: every runtime surface (CLAUDE.md, AGENTS.md, GEMINI.md) is generated from the catalog, never hand-edited. It implements the Interpretable Context Methodology (ICM) — folder-structure-as-architecture — to keep per-stage context at 2-8k tokens instead of a 30-50k monolithic prompt.

73 skills

35 routers + 24 competencies + 14 jarvis-os. 611 capabilities traced and dispositioned — no load-bearing capability dropped.

3 runtimes

One catalog runs on Claude Code, Antigravity and Codex. No per-runtime forks of logic.

Deterministic gates

A phase is "done" only when its artifacts exist on disk, not when a model asserts it.

Who it's for

Vibe coder

Builds mini and super apps in build-run-observe loops. Working code before long prose. Tests, security and evidence never bend for speed.

Good tasks: mini app, prototype, repair a small feature, internal tool, turn a rough need into a runnable app slice.

Knowledge worker

Delegates research, synthesis, briefs and decisions. Every non-trivial claim tagged and cited. Provenance preserved. Assumptions surfaced, not laundered into facts.

Good tasks: research a domain, operating brief, compare tools, sourced decision memo, playbook or FAQ.

Selection rule: if the task asks for runnable code → vibe-coder. If it asks for research or sourced documents → knowledge-worker.

FAQ

Can I hand-edit CLAUDE.md / AGENTS.md / GEMINI.md?

No. They are generated surfaces. Edit the canonical source (catalog, runtime core, delta or profiles) and regenerate with build-indexes.py. Hand changes are lost on regen.

Which runtime should I use first?

Whichever you already have. Claude Code reads CLAUDE.md, Codex reads AGENTS.md, Antigravity reads GEMINI.md. All three come from the same catalog.

How do I pick a profile?

vibe-coder for runnable software. knowledge-worker for research or sourced documents. The profile activates brand, quality and commercial rules when the deliverable belongs to the MetodologIA ecosystem.

What happens if I ask something ambiguous?

It emits a coverage_gap and asks before editing. It does not guess. It does not edit on assumption.

Can it show prices?

No, never in output. Effort in FTE-months + disclaimers (governance rule). Pricing is profile-scoped.
